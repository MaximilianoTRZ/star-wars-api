# ADR-015: Dashboard público con Grafana Cloud y scrape autenticado

## Estado

Aceptado

## Contexto

En local, Prometheus y Grafana corren con el `docker compose`. Para ver el dashboard con esa opción hay que clonar el repo y levantar el stack. El objetivo es tener además una URL pública con las métricas reales de la app desplegada en Render.

Render publica un solo puerto por servicio, y en local las métricas viven en el puerto de management (8081), que no se publica.

## Decisión

- Grafana Cloud (plan gratuito) lee las métricas de Render con la integración **Metrics Endpoint**: hace scrape de `/actuator/prometheus` cada 1 minuto.
- En el perfil `prod`, Actuator comparte el puerto público con la API (`management.server.port` igual a `server.port`).
- `/actuator/prometheus` exige HTTP Basic con un usuario propio (`METRICS_USERNAME` / `METRICS_PASSWORD`), separado de los usuarios de la API. Ese usuario solo puede leer métricas: no sirve para llamar a la API, que sigue pidiendo JWT.
- Si falta `METRICS_PASSWORD` o tiene menos de 16 caracteres, la app no arranca. Así el endpoint nunca queda abierto por un error de configuración.
- El dashboard del repo se importa en Grafana Cloud y se comparte con un link público de solo lectura.
- En local no cambia nada: Actuator sigue en el 8081 y Prometheus lo lee sin credenciales.

## Alternativas descartadas

- **Push por OTLP** (`micrometer-registry-otlp`): el endpoint de métricas no se expone, pero Grafana Cloud traduce los nombres de OTLP y algunas series no coinciden con las de Prometheus. Habría que mantener dos dashboards. Además, mientras Render duerme no se envía nada.
- **Prometheus o Grafana Alloy dentro de Render:** un servicio más, o dos procesos en el mismo contenedor, para una demo.
- **Dashboard solo en local:** obliga a clonar y levantar el stack para verlo.

## Consecuencias

- El dashboard con datos reales se ve desde una URL, sin levantar nada.
- Las métricas usan los mismos nombres que en local, así que el dashboard es el mismo archivo. Solo cambia el datasource al importarlo.
- El endpoint de métricas queda en internet, detrás de autenticación. Expone métricas técnicas y de negocio, nunca datos de usuarios: los tags tienen valores acotados y nunca incluyen lo que escribe el usuario.
- El scrape cada minuto mantiene despierta la instancia de Render: desaparece el arranque en frío y el servicio sigue dentro de las horas gratuitas del mes.
- Las alertas de `monitoring/alerts.yml` corren solo en local.
