# ADR-005: Usuarios en H2 en memoria

## Estado

Aceptado

## Contexto

Hacen falta usuarios con contraseña hasheada para el login. El único usuario necesario es uno de demo para probar la API; el registro self-service está fuera de alcance.

## Decisión

- Entidad JPA `UserAccount` en H2 en memoria.
- Al arrancar, un `ApplicationRunner` crea el usuario `demo`, con la contraseña de `DEMO_USER_PASSWORD`, si no existe.
- En `prod` la contraseña no tiene default: si la variable falta, la app no arranca.

## Alternativas descartadas

- **PostgreSQL:** obliga a levantar y configurar una base para probar la app, y el free tier de Render no tiene una base persistente gratuita.
- **`InMemoryUserDetailsManager`:** más simple, pero no muestra la capa de persistencia ni deja el camino listo para un registro.

## Consecuencias

- Cero infraestructura extra.
- Los usuarios se pierden al reiniciar. Es aceptable, porque el demo se recrea solo.
- Migrar a Postgres es cambiar el datasource y agregar el driver; el código JPA no cambia.
