# ADR-019: Servidor MCP stateless con el JWT en un header

## Estado

Aceptado

## Contexto

La Fase 6 expone el catálogo como servidor MCP para que clientes de IA (Claude Code, Claude Desktop, Cursor) lo consulten con tools. El transporte Streamable HTTP de MCP tiene dos modos: con sesión, donde el servidor guarda un `Mcp-Session-Id` en memoria y puede mandar notificaciones al cliente, y stateless, donde cada request se resuelve sola. La API ya es stateless (JWT, sin sesión HTTP) y está pensada para escalar con réplicas detrás de un load balancer.

La especificación de MCP define autorización con OAuth 2.1, con descubrimiento del servidor de autorización y registro dinámico de clientes. La API emite sus propios JWT con `POST /api/v1/auth/login`.

## Decisión

- Spring AI 2.0.2 con `spring-ai-starter-mcp-server-webmvc` y `spring.ai.mcp.server.protocol: STATELESS`, en `/mcp`.
- Ocho tools de solo lectura (`readOnlyHint`), dos por recurso (`search_*` y `get_*`), que delegan en `CatalogService` y devuelven los mismos DTOs que REST como JSON.
- Autenticación con el mismo JWT, en el header `Authorization: Bearer <token>`, validado por la cadena de seguridad antes de llegar a MCP. `/mcp` exige el scope `catalog:read`, igual que `/api/v1/**` y `/graphql`.
- Cada tool arma su propio resultado: un ID inexistente es un resultado normal con un mensaje claro y cualquier falla es un resultado con `isError` y el mismo texto público que el `detail` de REST. Nunca se expone el mensaje de una excepción interna.

## Alternativas descartadas

- **Streamable HTTP con sesión:** guarda estado por cliente en memoria. Con varias réplicas habría que compartirlo o usar sticky sessions, y no usamos lo que agrega (notificaciones del servidor, sampling).
- **OAuth 2.1 del spec de MCP:** exige un servidor de autorización con descubrimiento y registro dinámico de clientes. Es lo que correspondería con un Identity Provider externo (ver "Cómo lo escalaría"); para este alcance alcanza el JWT propio en un header, que Claude Code y `mcp-remote` soportan.
- **Un servicio MCP aparte que llame a la API REST:** otro deploy y otra configuración, para traducir llamadas que el mismo proceso ya resuelve (ADR-016).

## Consecuencias

- `/mcp` responde JSON plano: se prueba con curl y con Postman, además de con un cliente de IA.
- Cualquier réplica atiende cualquier llamada, sin estado compartido.
- El token vence a la hora: el cliente de IA tiene que repetir el login y volver a configurar el header. Está documentado en el README.
- Claude Desktop no acepta headers en conectores remotos; se usa con el proxy `mcp-remote`, que sí los manda.
