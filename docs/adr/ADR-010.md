# ADR-010: Render free tier con Docker

## Estado

Aceptado

## Contexto

La API tiene que estar desplegada en un servicio gratuito, accesible desde una URL pública, desde la Fase 0.

## Decisión

- Render, servicio web construido desde el `Dockerfile` del repo, con auto-deploy desde `main`.
- `SPRING_PROFILES_ACTIVE=prod`. Los secretos (`JWT_SECRET`, `DEMO_USER_PASSWORD` y, desde la Fase 3, `METRICS_USERNAME`/`METRICS_PASSWORD`) se cargan como variables de entorno en Render, nunca en el repo.
- Health check en `/actuator/health` en la Fase 0; desde la Fase 3, en `/livez`. Es un probe de liveness, así que una caída de SWAPI no hace que Render reinicie la app.

## Alternativas descartadas

- **Heroku:** ya no tiene plan gratuito.
- **Vercel:** no corre aplicaciones Java de larga duración.
- **AWS (EC2 + Docker Compose + reverse proxy):** para una demo agrega costo, administración de la instancia, HTTPS y un pipeline de deploy propio, sin cambiar lo que se evalúa.

## Consecuencias

- Deploy directo desde el Dockerfile, sin configuración propietaria.
- El free tier duerme la instancia: el primer request puede tardar ~30–60 s. Está avisado en el README, junto con la opción de correr local con un comando. Desde la Fase 3 el scrape de Grafana Cloud la mantiene despierta (ADR-015).
- Render publica un solo puerto por servicio: en `prod`, Actuator comparte el puerto con la API.
- En Render corre únicamente la app. Prometheus y Grafana corren con el `docker compose` local, y el dashboard público sale de Grafana Cloud.
