# ADR-008: `RestClient` sincrónico + virtual threads

## Estado

Aceptado

## Contexto

Cada request a la API se traduce en una llamada (o ninguna) a SWAPI. El trabajo es casi todo I/O.

## Decisión

- Cliente HTTP `RestClient` (sincrónico), construido desde el `RestClient.Builder` de Boot, con `JdkClientHttpRequestFactory` y timeouts explícitos (connect 2 s, read 10 s).
- `spring.threads.virtual.enabled=true`: cada request corre en un virtual thread, así que esperar a SWAPI no bloquea threads de plataforma.

## Alternativas descartadas

- **`WebClient` reactivo:** concurrencia equivalente para I/O, pero código y tests más complejos, y obliga a sumar WebFlux.
- **`@HttpExchange` (interfaces declarativas):** cómodo, pero el mapeo de errores y de las tres formas de respuesta de SWAPI queda menos explícito.

## Consecuencias

- Código imperativo, fácil de leer y de testear con WireMock.
- Las métricas `http.client.requests` llegan gratis en la Fase 3, porque se usa el builder autoconfigurado.
