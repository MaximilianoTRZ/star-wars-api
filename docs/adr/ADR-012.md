# ADR-012: `wiremock-standalone` en tests

## Estado

Aceptado

## Contexto

WireMock embebe un servidor Jetty. Spring Boot 4.1.2 gestiona Jetty 12.1, y la variante `wiremock-jetty12` choca con esa versión.

## Decisión

Usar `org.wiremock:wiremock-standalone` 3.13.2 (scope `test`). Trae su propio Jetty reubicado dentro del jar.

## Alternativas descartadas

- **`wiremock-jetty12`:** conflicto de versiones con el Jetty que gestiona Boot 4.
- **`wiremock-spring-boot`:** suma una integración más para algo que se resuelve con `WireMockExtension` + `@DynamicPropertySource`.

## Consecuencias

- La app corre sobre Tomcat y el Jetty de WireMock queda aislado. No hay conflicto de classpath.
- El jar standalone es más pesado, pero solo afecta al classpath de test.
- Con `WireMockExtension` estático no se usan clases `@Nested` en los ITs: cada clase anidada reinicia WireMock en otro puerto y el contexto de Spring queda apuntando al anterior.
